# 変更点（v8_fix3 → v9：ローカルサーバー + Edge/Chrome アプリ表示）

## 1. 概要

pywebview（WebView2）で画面を出す方式をやめました。代わりに、Python が `127.0.0.1` でローカルサーバーを立て、Edge（無ければ Chrome）の `--app` モードで専用ウィンドウを開きます。

これで WebView2 ランタイムの有無に左右されなくなり、依存も bleak だけになりました。

| ファイル | 変更 |
|---|---|
| `server.py` | **新規**。ローカルサーバー、ブラウザ起動、終了検知、二重起動対策、エラー表示、ログ |
| `main.py` | pywebview の除去、保存先の切り替え（DATA_DIR）、ログ、BLE エラーの説明文、エクスポートの分割（後述）、起動部分 |
| `index.html` | 橋渡しスクリプトを1つ追加（`<script>` 1ブロック）。既存行の変更は3行だけ（フォント2行、ログ欄の「ログの場所を開く」ボタン） |
| `requirements.txt` | pywebview を削除。`bleak>=0.22,<2` |
| `setup.bat` / `run.bat` / `build_exe.bat` | pywebview 前提の記述を削除。日本語のメッセージボックスを追加（ファイルは ASCII のみ・CRLF のまま） |
| `README.txt` | **新規**（日本語の利用者向け説明） |

## 2. 通信の置き換え（3-1）

- **呼び出し方**：画面からの呼び出しは `POST /api/<メソッド名>`（本文 `{"args":[...]}`）です。応答は、成功なら `{"result": 値}`、失敗なら HTTP 500 の `{"error": "ValueError: ..."}` です。
- **画面側の受け口**：index.html に「旧 `window.pywebview.api` と同じ形のオブジェクト」を作る橋渡しを足しました。
  - `pywebviewready` も橋渡しから発火させます。
  - そのため `call()`・`cmd()`・TX送信ループ（`a.send_teach_frame` など）・`poll_events` を含め、**既存の画面ロジックは書き換えていません**。依頼では `call()` と `poll_events` の中身を差し替える案でしたが、TX送信ループも `api()` を直接呼んでいたため、この方式のほうが差分が小さくなりました。
- **エラーの見え方**：失敗時は、画面のログに旧版と同じ `[UI ERROR] 名前: ValueError: ...` の形で出ます。
- **呼べるメソッドの制限**：`server.py` の `API_METHODS` に書いたものだけです。`_` で始まる内部メソッドや `__init__` などは呼べません。
- **生存通知**：`/api/_alive` です。ロボットへの `heartbeat` とは別物です。

## 3. セキュリティ（3-2）

- **待ち受け先**：`127.0.0.1` だけで待ち受けます。
- **ポート**：48573〜48577 を優先し、使用中なら空きポートを使います（理由は第9章）。
  - Windows では `SO_REUSEADDR` を使いません。Windows のこのオプションは「使用中のポートにも重ねて待ち受けられる」という意味になるためです。
- **トークン**：起動ごとにランダムに作り、URL（`?t=`）に入れます。
  - `/api/` の要求は `X-Token` ヘッダ（生存通知の `sendBeacon` だけは URL）で照合します。
  - `GET /` もトークンが必要です。
- **Host の確認**：`127.0.0.1:ポート` か `localhost:ポート` 以外は拒否します（DNS リバインディング対策）。
- **Origin の確認**：POST では必須で、`http://127.0.0.1:ポート` / `http://localhost:ポート` 以外は拒否します。

## 4. 起動とウィンドウ（3-3）

- **ブラウザの探し方**：Edge（Program Files (x86) → Program Files → LocalAppData）→ Chrome → PATH 上の chromium / google-chrome など、の順です。
- **専用プロファイル**：`--user-data-dir` で、普段のブラウザと分けています。
  - パスに ASCII 以外の文字が入る場合は、`C:\ProgramData\RobotMotionStudio\browser_profile` → `C:\Users\Public\RobotMotionStudio\browser_profile` の順に切り替えます。
- **見つからない場合**：既定のブラウザで開き、画面のステータスとログに「専用ウィンドウでは開けませんでした」と出します。
- **終了の判定**：次のどれかで終了します。終了時は BLE を `_close_client()` で切断し、asyncio ループとサーバーを止めます。
  - 閉じる操作（`beforeunload` の `sendBeacon`）のあと、5秒以内に再読み込みが来なかった
  - 生存通知（Worker から3秒ごと）が25秒途絶え、かつ起動したブラウザのプロセスも終わっている
  - ブラウザのプロセスが終わり、生存通知も12秒途絶えた
  - 起動から120秒たっても画面が一度も来ない（ブラウザが起動できなかった場合）
- **ブラウザのプロセスも見ている理由**：最小化したまま長く置くと、ブラウザが通知の間隔を大きく間引くことがあるためです（Worker は間引かれにくいので Worker から送っています）。
- **二重起動**：既存のウィンドウを案内する方式にしました（第9章）。

## 5. 保存ダイアログ（3-4）と旧版との違い

### 5-1. 方式
画面の橋渡しの中で、File System Access API（`showSaveFilePicker` / `showOpenFilePicker`）を使います。呼び出し元（`saveMotions`・読込ボタン・`exportHeader`）に返す値の形は、旧版の Python 版と同じです。

| 旧 API | 新しい処理 |
|---|---|
| `save_text_file` | 保存先を選ぶ → 書き込み → ファイル名を返す（キャンセルは `null`） |
| `load_text_file` | ファイルを選ぶ → `{fileName, text}` を返す（キャンセルは `null`） |
| `export_header` | 保存先を選ぶ → 今の内容を読む → Python の `export_header_build` が内容を作る → 変更があるときだけ書き込む |

### 5-2. エクスポートで旧版と同じ点
- 校正値の引き継ぎ（未接続なら既存ファイルから）
- 内容が同じなら書き込まない（`unchanged`）
- 校正値がないときのエラー文
- ログの書式（`[EXPORT] … を書き出しました（モーション n 件 / 校正値: …）`）
- 書き込みはブラウザが一時ファイルに書いて最後に置き換えるので、旧版の tmp → replace と同じく、途中で失敗しても壊れたファイルは残りません。
- 出力内容は旧版の生成関数とバイト一致します（テスト済み）。

### 5-3. 旧版との違い
- **`.bak` の場所（判断事項）**：ブラウザの機能では「選んだファイルの隣」に別のファイルを作れません。そのため、上書き前の内容は `保存先(DATA_DIR)\backup\ExportData.h.bak` に1世代だけ退避します。退避先はログに表示します。
- **ログに出るのはファイル名だけ**：ブラウザは保存先のフルパスを教えないため、旧版のようにフルパスは出せません。`settings.exportPath` にもファイル名だけが入ります。この値は旧版でも保存先を決めるのには使っていなかったので、データ形式は変わりません。
- **空のファイルの削除**：保存先に新しい名前を選ぶと、ブラウザがその時点で空のファイルを作ることがあります。エクスポートが失敗した場合（校正値がないなど）は、その空ファイルを消します。
- **「前回の保存先」**：ファイルの場所を IndexedDB（専用プロファイルの中）に覚えて、次回は `startIn` でそこから開きます。モーション JSON とエクスポートは別々に覚えます。
  - フォルダのパスではなく「前回選んだファイル」を基準に開きます。
  - ポートが変わると別扱いになって忘れます。
- **クリックの必要**：ブラウザは「クリックの直後」にしか保存先の画面を開けません。間に確認ダイアログが入って開けなかったときは、「保存先を選ぶ」ボタンを出して、もう一度押してもらいます。
- **改行コード**：モーション JSON を Python で書いていた旧版は、Windows では CRLF になっていました。新しい版は LF です。読み込みには影響しません。ExportData.h は旧版も LF なので同じです。
- **File System Access API が無いブラウザ（Firefox など）**：
  - 保存は「ダウンロード」フォルダへ、読込はファイル選択画面で行います。初回にログで日本語の説明を出します。
  - 未接続でのエクスポートは、校正値を引き継ぐ既存の ExportData.h を選んでもらいます。

## 6. 保存先・ログ（3-5・第4章）

- **保存先（DATA_DIR）**：基本は APP_DIR（main.py または exe と同じフォルダ）です。
  - 書き込めないときだけ `%APPDATA%\RobotMotionStudio` を使い、初回は旧ファイル（settings.json / pose_library.json）をコピーして引き継ぎます。
  - 保存は tmp → `os.replace` のまま（原子置換）です。
- **ログ**：`DATA_DIR\robot_motion_studio.log`（1MB × 3世代）です。
  - 画面のログに出る内容（`Api.log`）も、すべてファイルに残ります。
  - ログ欄に「ログの場所を開く」ボタンを付けました。
- **致命的な失敗**：Windows のメッセージボックス（`MessageBoxW`）で日本語で知らせます。対象は、index.html が無い、ポートが取れない、想定外の例外、などです。
- **zip の中から起動**：パスに `.zip\` や `\Temp1_` が含まれていたら、メッセージを出して終了します。run.bat でも同じ確認をします。
- **Bluetooth のエラー**：オフ、アダプタが無い、bleak が無い、を見分けて、ログのエラー文の後ろに原因と対処を添えます（`_ble_hint`）。BLE の処理そのものは変えていません。
- **フォント**：`'Noto Sans CJK JP'` を末尾側に追加しました。

## 7. 依存・ビルド（3-6）

- **requirements.txt**：`bleak>=0.22,<2`（Python 3.10〜3.12 を想定）。
  - こちらではネットに繋がらず、今お使いの bleak の版を確認できていません。今のPCとまったく同じにしたい場合は、今の `.venv` で `pip freeze` した結果に置き換えてください。
- **setup.bat**：`py -3.12` → `-3.11` → `-3.10` → `py -3` → `python` の順に探します。失敗したときは日本語のメッセージボックスを出します。
- **run.bat**：
  - zip の中からの起動を確認します。
  - `.venv` が無ければ setup を実行します。
  - 起動は `pythonw`（黒い画面なし）です。エラーはメッセージボックスとログに出ます。
  - `PYTHONUTF8=1` を設定します。
- **build_exe.bat**：
  - onedir・`--windowed` のままです。`--collect-all webview` を削除し、`--hidden-import server` を追加しました。
  - bleak / winrt の collect はそのままです。PyInstaller は `>=6.3,<7` にしました。README も同梱します。
- **windowed の exe**：`sys.stdout` / `sys.stderr` が None になるので、devnull に差し替えています（ログはファイルへ）。
- **UTF-8**：run.bat では `PYTHONUTF8=1` を設定しています。exe 版は UTF-8 モードにしていません。代わりに、ファイルの入出力はすべて `encoding='utf-8'` を明示しています。サブプロセスの引数はリストで渡します（Windows では Unicode のまま渡ります）。

## 9. 判断が必要だった箇所

- **二重起動 →「既存ウィンドウを案内」にしました。**
  - 起動中は保存先に `instance.json`（ポート・トークン）を置きます。2回目の起動はそれを見て `/api/_ping` で確認し、動いていれば同じサーバーのウィンドウをもう1つ開いて、すぐ終わります。
  - 理由：2つのアプリが同じロボットに BLE で同時に接続しようとすると、接続の取り合いになります。また、settings.json / pose_library.json を同時に書き換えて内容が食い違います。初心者が起動ボタンを2回押す場面も多いので、「2回押しても1つのアプリ」が安全です。
  - `instance.json` が残っていても（強制終了など）、応答が無ければ無視して新しく起動します。
- **`.bak` の置き場所 →「保存先のフォルダ」ではなく「アプリの保存先の backup フォルダ」にしました**（第5章）。
  - 保存先の隣に置くには、ファイルではなくフォルダを選んでもらう方式にする必要があります。その場合はファイル名を自由に選べなくなるので、こちらを選びました。
- **ポート → 固定の候補（48573〜）を優先し、使用中なら空きポートにしました。**
  - 理由：ブラウザに覚えさせる「前回の保存先」が、ポートごとに別扱いになるためです。安全性はトークンで確保しています。
- **index.html → `call()` / `poll_events` を書き換えず、`window.pywebview.api` 互換の橋渡しを足しました**（第2章）。

## 10. 確認したこと（Linux のコンテナ上、Python 3.11 / 3.12 / 3.13、Chromium）

- **旧版との出力の一致**：同じ入力に対して、旧 Api を直接呼んだ結果と新サーバー経由の結果が一致しました（27項目）。
  - 対象：`check_motion_name`、未接続時の各コマンドの戻り値、`save_app_json` / `load_app_json`、例外の文言、`upload_and_play` のログ、settings.json のバイト列、`build_frame` / `hash16`
- **画面の操作**（Chromium・日本語を含むパス）：
  - 起動して設定・ポーズライブラリを読み込む
  - モーション作成（名前の検証を Python で行う）
  - JSON の保存・読込
  - エクスポート（旧版とバイト一致、`.bak` 退避、変更なしの判定、空ファイルの削除、エラー文）
  - 「保存先を選ぶ」ボタンでの再試行、キャンセル
  - Firefox などで使う代わりの方法（ダウンロード／ファイル選択）
  - コンソールエラーなし
- **不正な要求の拒否**：トークン無し、違うトークン、Origin の不一致または無し、Host の不一致、内部メソッドの呼び出しを、すべて拒否しました。
- **プロセスの動き**（実際に `python main.py` を起動）：

  - ウィンドウを閉じると約6秒で終了し、`instance.json` を削除してログに残す

  - ブラウザが見つからないときは、既定ブラウザと日本語の案内で動き、25秒で終了する

- **書き込めないフォルダ**：別ユーザーで実行し、`%APPDATA%` 相当のフォルダへ切り替わって旧ファイルを引き継ぐことを確認しました。
